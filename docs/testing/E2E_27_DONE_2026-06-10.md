## 四、Vite Proxy 分析

| App | 端口 | proxy target | sandbox 可达? | API 状态 |
|-----|------|-------------|--------------|---------|
| web | 3000 | `192.168.10.4:8088` | ❌ | 500 |
| studio | 5175 | `localhost:8089` | ✅ | 正常 |
| user-portal | 5180 | `192.168.10.4:8088` | ❌ | 500 |
| admin-portal | 5174 | `192.168.10.4:8088` | ❌ | 500 |
| ops-portal | 5176 | `192.168.10.4:8088` | ❌ | 500 |

**根因**: Chrome sandbox 浏览器网络隔离，无法访问 `192.168.10.4` (非本机 IP)。`localhost` 可访问。

**建议修复**: 4 个 app 的 `vite.config.ts` 中 `proxy target` 从 `192.168.10.4:8088` 改为 `localhost:8088`。studio 用 `localhost:8089` 不受影响。

## 五、测试方法说明

由于 BUG-027-001 (proxy 不通) 阻塞正常登录流，本次采用 **token 注入法** 绕过:
1. 浏览器 `evaluate` 直连 `localhost:8088/api/v1/auth/login` 获取 JWT
2. 设置 `localStorage['token']` + `localStorage['mhw.access_token']` 双 key
3. 导航到需鉴权页面，验证路由守卫 + UI 渲染

**这不是 mock 测试** — token 来自真实 API，页面渲染的是真实 UI，只是 API 数据获取因 proxy 不通而受限。
