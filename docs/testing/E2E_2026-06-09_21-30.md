- **症状**: 输错密码 (`WrongPwd!`) → 也能登到 /dashboard
- **console**: 无错误

- **修法**: 改成调 `POST /v1/auth/login` 真 API, 失败显示错误
- **影响**: 邮箱密码登录**完全不可用** (mock)

### 🟡 P1: web dashboard 数据硬编码
- **症状**: dashboard 显示"3 个进行中项目 / 12 已发布 / 248 素材 / 5 成员", 跟 DB 无关
- **根因**: DashboardView 是 W2 占位版, 写死了 4 个数字 + 3 个假项目
- **修法**: 接真 API `GET /v1/projects?status=active&limit=3` + 统计 API
- **影响**: 演示看着 ok, 但**用户/项目/作品数 跟实际不符**

### 🟡 P1: web dashboard 项目卡 不可点击
- **症状**: "最近项目" 3 个卡片 + "→" 箭头, 点击**啥都不发生** (cursor: pointer 但无 onclick)
- **根因**: W2 占位, 没接 router
- **修法**: 加 `<RouterLink :to="`/projects/${p.id}`">` 包整卡片, 或加 @click="goProject(p.id)"
- **影响**: 用户卡住

### 🟡 P1: studio "+ 新成员" 用 window.prompt
- **症状**: 点 + 新成员 → 弹 90 年代 prompt 输入框
- **修法**: 换 modal 组件 (跟 user-portal 的 create project modal 一样)
- **影响**: 丑 + 多步 (邮箱→名字→角色) 体验差

## 💡 虾总助反思

### 之前测试的 4 大问题
1. **查 console error 代替真点按钮** — syntax error 一查就有, 但 L2 林染写完没真点, 虾总助也没真点, 留给梁总
2. **querySelector 看元素存在 ≠ 按钮能用** — "打开" 按钮**有元素** + **有 click handler** ≠ 点击后流程对
3. **看 DOM 改没改 ≠ 业务对** — 主题 data-theme 改了 ≠ 视觉切了 ≠ 用户感受对了
4. **测一个 view 就报告"测了"** — 6 个 view 只测 1 个就下结论, 实际上 5 个没碰

### 改进方法
- ✅ **真点**每个按钮, 看终态 (URL 跳了吗 / 元素出现了吗 / 数据真存了吗)
- ✅ **看截图**不是看 console, 视觉问题是 console 看不出来的
- ✅ **每个 view 必测**, 不接受"看代码 OK 就行"
- ✅ **错码报错 = 立即现场修**, 不留给林染"下次再说"
- ✅ **真用户路径**: 首页 → 登录 → 选项目 → 编辑 → 导出, 一条龙

### 写进 .learnings/ERRORS.md
1. "console 无 error" ≠ "用户能用"
2. 5 真 view 写完没人真点开, 5 个潜在白屏/bug 漏到梁总
3. 林染交付 = 虾总助真点验收, 不能省略
4. 找 syntax error 的最简方法: 在浏览器看 console, 不要在 IDE 静态分析 (因为 Vite HMR 会把模块加载错误延迟暴露)
