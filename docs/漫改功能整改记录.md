## 二、已落地整改（代码实证）

### F-01 步骤导航完成度校验闸门（高优先级 · 已闭环）

- **问题**：原 `canProceed()` 硬编码 `return true` 且从未被调用，底部"下一步"直接 `markCompleted + goNext`，用户可空跑 10 步、步骤"假完成"，下游用空数据生成空白视频。
- **整改**（文件 `apps/web/src/views/create/StoryboardEditorView.vue`）：
  1. 删除死代码 `canProceed`，新增 `checkStepGate(index)`，按 `step.key` 判定各步骤必填项：
     - `setup`：项目名称非空
     - `upload`：`hasUploadedNovel`（小说文本 ≥10 字）
     - `character`：至少 1 角色且其主视觉图已生成
     - `scene`：至少 1 场景且其场景图已生成
     - `storyboard`：分镜数 > 0
     - `video`：已生成镜头视频数 > 0
     - `compose`/`enhance`/`dubbing`/`final`：对应成片/增强/配音/最终 URL 存在
  2. 新增 `currentGate` computed 与 `onNextClick()`；底部"下一步"改为 `@click="onNextClick"`，未达标时按钮置灰（`.sbe-nav-btn--blocked`）并实时显示缺失项（`currentGate.reason`，`role="alert" aria-live="assertive"`）。
  3. 兼顾可访问性：按钮保持可聚焦（未用原生 `disabled`），拦截时明确语音/屏幕阅读器播报，避免"点了没反应"。
- **验证**：`canProceed` 已彻底移除；`currentGate`/`onNextClick` 脚本与模板引用闭合（grep 实证）。

### F-03 草稿持久化增强与显式告警（高优先级 · 已闭环）

- **问题**：草稿仅存 `sessionStorage`，关闭页面/标签页即丢稿；5MB 配额超限时静默降级覆盖为 compact（丢弃全部已生成图 URL），用户无感知。
- **整改**（同文件）：
  1. 草稿 `DRAFT_KEY_SB`、小说文本 `mhw:storyboard:novel-text`、导出交接 `mhw:storyboard:export-data` 由 `sessionStorage` 改为 `localStorage`——跨会话保留，关页不丢稿。
  2. **保留语义隔离**：`HISTORY_KEY_SB`（分镜历史）与 `mhw:bridge`（跨页桥接）仍为 `sessionStorage`，不改其 tab 级隔离意图。
  3. 5MB 降级逻辑重构：不再静默覆盖完整草稿（避免已生成图丢失），改为置 `draftSaveWarning` 并 `console.warn`；页脚新增告警条（`role="alert" aria-live="polite"`，可关闭），明确告知"本地存储可能已满，请尽快导出"。
- **验证**：静态校验通过；`localStorage` 容量阈值行为需浏览器实测。

### F-04 生成图 URL 参考图前端就绪（中高 · 前端侧闭环，需后端配合）

- **问题**：生成图 URL 为 localhost-only，"不满意重新生成"时无法作为参考图传入 Seedream，结果漂移（功能性落差）。
- **整改**：`regenerateView` 中，当已生成图为**非 localhost 公网 URL** 时，自动作为 `referenceImages` 传入，提升重生成一致性；localhost 旧数据自动跳过。
- **说明**：此为**前端就绪**改造；根因修复（图转存对象存储、返回公网 URL）属后端任务，联调后本逻辑自动生效，无需二次前端改动。

### F-02 单文件 11607 行巨组件（高优先级 · 已完成专项评估，待实施）

- **现状**：`StoryboardEditorView.vue` 单文件 11607 行，10 步全内联，首屏体积/卡顿/回归风险高。
- **增量拆分方案**（降低回归风险，禁一次性重写）：
  1. **抽 utils**：`STEPS` 定义、`checkStepGate` 步骤校验、prompt 构建、URL 判断等外提至 `utils/storyboard/`。
  2. **拆子组件**：按步骤拆 `steps/StepSetup.vue` … `StepFinal.vue`，父组件仅负责 stepper + 状态编排。
  3. **状态上移**：`characterAppearances/shots/extractedScenes/...` 由 `generationStore` 统一管理，子组件经 store 读写，减少 props 透传。
  4. **分阶段**：先抽 utils+store（低风险）→ 逐步骤外提子组件（每步独立验证）→ 删减主文件。
- **风险**：一次性重写风险极高，必须增量；每步配套回归生成/导出链路。列入第二阶段重点。

### F-08 浅色主题对比度（已闭环 · 根因修复）
- **根因（两处）**：
  1. `MainLayout.vue` `.layout` **硬编码深色令牌**（`--text-primary:#E8EAED` 等主题已拥有的变量），覆盖浅色主题——整站（含路由视图）文字在浅色主题下被强制为近白色，白底白字不可见。
  2. `:root`（`tailwind.css`）默认深色 `--bg-tertiary:#2D2D5E`/`--bg-card:#141A2E`，而浅色主题（minimal-light/national-ink/creator-orange）**从未覆盖**；`StoryboardEditorView` 44 处 `var(--bg-tertiary)` 在浅色主题下回退到深色表面 + 深色文字 = 不可见。
- **修复（类型安全 CSS，零 TS 影响）**：
  - `MainLayout.vue` `.layout` 改为**主题感知**：`--bg-*`/`--border-*`/`--accent-*` 映射为 `var(--主题令牌, <原深值兜底>)`；移除对 `--text-*`/`--accent` 的硬编码覆盖，改由主题/`:root` 提供（深色主题值与原字面量一致，故深色外观不变；浅色主题首次真正套用）。
  - `tailwind.css` 末尾补充分组令牌（`.theme-minimal-light/.national-ink/.creator-orange` 给浅值；`.theme-dark-workshop/.neon-cyber` 给与现状一致的深值）：`--bg-tertiary/--bg-surface/--bg-card/--surface-1..3/--border-color/--border-subtle/--error`，使编辑器深表面在浅色主题下正确变浅。
