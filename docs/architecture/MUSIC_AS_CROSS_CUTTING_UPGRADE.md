# 音乐生成深度融合升级方案

> 梁总指示：音乐不能只是点缀，要作为平台基础能力融进每个子页面
> 统筹：陈远枢（运营总监/总调度）
> 日期：2026-06-18
> 基底：PORTALS_ARCHITECTURE.md（2026-06-06）+ SITE_REFACTOR_PHASE1（2026-06-10）

---

## 一、现状问题

当前音乐/音频在整个产品架构中的存在感：

| 站点 | 音乐存在度 | 现状 |
|------|-----------|------|
| 用户后台 (app) | ❌ 0% | 素材库只有角色/场景/道具/分镜/模板，无音频分类 |
| 创作者工作台 (studio) | ⚠️ 2% | 编辑器右侧面板只有一行 "BGM"（481行），无展开面板 |
| 业务总后台 (ops) | ❌ 0% | 内容审核无音频维度，内容运营无配乐管理 |
| 平台总后台 (admin) | ❌ 0% | 服务列表无 music-service |
| 开发者后台 (dev) | ❌ 0% | API文档无音乐生成接口 |
| 电商生成线 | ❌ 0% | 短视频/笔记素材无音频输出支持 |

**根本原因**：音乐生成是作为"附加功能"规划，不是作为"平台能力"设计。导致各子页面在信息架构、UI布局、API设计、工作流编排上都漏掉了音频这个维度。

---

## 二、改造原则

1. **横切能力** — 音乐生成不是独立板块，是像"搜索"一样渗透到每个功能的横切能力
2. **不另起炉灶** — 不新建一个"音乐站点"，而是改造现有5个后台+1个电商线
3. **渐进式渗透** — 分两层：L1 把"音乐"塞进现有页面结构；L2 把"音乐生成"变成工作流标准步骤
4. **一次到位** — 改架构文档的同时改权限矩阵、路由设计、API规范

│  │ ▓░░░░░▓░░░░░░░░░░░░░░░░░        │     │

│                                           │
│  ┌─── 生成配乐 ─────────────────────┐     │
│  │  当前分镜：废墟探索（情绪: 紧张）    │     │

**核心功能**：
- **时间轴可视化**：BGM/音效/配音三轨叠加，支持拖拽对齐
- **AI 选曲**：根据当前分镜的情绪标签自动推荐BGM
- **AI 生成**：输入文字描述或选择风格，AI 生成专属BGM
- **音效叠加**：从素材库拖入音效到指定时间点
- **音量控制**：每个轨道独立音量+整体音量

## 九、技术架构改造

### 9.1 新增服务

| 服务 | 端口 | 框架 | 功能 | 依赖 |
|------|------|------|------|------|
| music-generation-service | 8092 | Express | 音乐生成（文字→音乐/情绪匹配/变奏）| MiniMax M3 API / Suno API |
| audio-processing-service | 8093 | Express | 音频处理（裁剪/混音/格式转换/音量标准化）| FFmpeg |

### 9.2 工作流（workflow-engine）改造

当前工作流步骤：S1 剧本拆分 → S2∥S3 角色+场景 → S4 分镜 → S5 图生成 → S6∥S7 视频+配音 → P5 合成

改造后增加配乐步骤：

```
                  ┌─→ S6 视频生成 ─┐
S1→S2∥S3→S4→S5─→┤                ├─→ S8 配乐生成 ─→ P5 合成
                  └─→ S7 TTS 配音 ─┘
                        ↑
                  新增 S8 并行路线

S8 配乐生成 内部流程：
┌─ 分析分镜情绪标签 → 匹配或生成BGM
├─ 分析场景类型 → 添加建议音效
├─ 音量平衡（BGM/配音比例预设）
└─ 输出音频轨道元数据 → 缓存到 Redis
```

### 9.3 Gateway 新增路由

```
/v1/audio/*            → music-generation-service :8092
/v1/audio/process/*    → audio-processing-service :8093
/v1/assets/audio/*     → asset-service :8085（复用已有资产服务）
```

### 9.4 资产存储扩展

asset-service 增加音频类型支持：

```typescript
type AssetType = 'image' | 'video' | 'audio' | 'document'

// audio 子类型
type AudioSubType = 'bgm' | 'sfx' | 'voiceover' | 'dialogue'

interface AudioMetadata {
  duration: number      // 秒
  format: 'mp3' | 'wav' | 'flac' | 'aac' | 'ogg'
  sampleRate: number    // Hz
  channels: number      // 1=mono, 2=stereo
  bpm?: number          // BGM专用
  mood?: string[]       // 情绪标签
  genre?: string[]      // 风格标签
  waveform?: string     // 波形数据URI（用于预览）
}
```

## 十三、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| MiniMax M3 音乐质量不达预期 | 中 | 用户不满意BGM质量 | 预留 Suno API 备选，L2阶段上线前先做A/B测试 |
| 音频处理性能瓶颈（FFmpeg） | 中 | 合片速度变慢 | audio-processing-service 用 worker 队列异步处理 |
| 音频存储成本暴增 | 中 | 存储费用超预算 | 1. 限制单次生成时长（30s以内）2. 自动清理7天前的临时音频 |
| 配乐版权纠纷（AI生成相似度过高） | 低 | 法律风险 | MiniMax M3 + Suno 均有版权保护声明，生成结果唯一性保证 |
| 三轨时间轴UI复杂度高 | 中 | 用户体验不佳 | L1先做简单版本（BGM单轨），L2再上完整三轨时间轴 |
