## 4. 模板必带 3 关键规则 {#3规则}

派单 22+32+33E 跑挂教训——以下 3 条规则模板里必须显式写出:

### 规则 1: 小批量 1 站/批 (来源: 派单 22+33E)

```markdown
### 🔴 规则 1: 小批量, 1 站/批
- 每批只改 1 个站点 (不要一口改 5 站)
- 每批完成 → 验收 (cURL/浏览器截图/E2E) → 再下一批
- 验收没过的 → 不准开下一批
- **违例后果**: 5 站同时爆, 谁也定位不到 bug (派单 33 惨案)
```

### 规则 2: 每批必报 + MEMORY 自更新 (来源: 派单 33E)

```markdown
### 🔴 规则 2: 每批必报 + MEMORY 自更新
- 每批完成 → 立刻写 1 行报告到派单文件 (不是做完才报)
- 每批完成 → 立刻 `edit` 更新 `<名>_MEMORY.md` "## 个人事件记录" 段
- 批次格式: `### 批 N/共M: <站名> ...`
- **违例后果**: 跑挂不知道怎么死的, 虾总助看不到中间产物 (派单 33E 惨案)
```

### 规则 3: 重启 vite 不杀进程 (来源: 派单 32)

```markdown
### 🔴 规则 3: 重启 vite 不杀进程 (仅前端任务)
- 改 vue → `vite` HMR 自动刷新, 不需要重启
- 如果需要重启: **先检查端口是否在跑**, 再启动
- 启动命令: `npx vite --port <端口> &` (非 pnpm dev, 子进程 PATH 不可靠)
- **违例后果**: 杀了旧进程但不启动新进程, 页面 404 (派单 32 惨案)
```

## 8. 违例示例 (反面教材) {#违例}

### 违例 1: 派单不带 4 件套
```markdown
# ❌ 派单 X: 林染修 LoginView
改 LoginView.vue, 把登录按钮颜色改蓝
```
**问题**: 没有角色/记忆/行为准则/红线, 林染不知道自己是谁, 凭啥改, 改到什么程度.

### 违例 2: 完工不报 MEMORY 自更新
```
DONE — 林染 · 修 LoginView
改完了.
```
**问题**: 没有 MEMORY 自更新, 下次林染接活不知道自己干过啥.

### 违例 3: 一口改 5 站
```
批 1: 改 admin + ops + studio + web + user-portal 5 站
```
**问题**: 5 站同时爆无法定位 (派单 33 惨案).
