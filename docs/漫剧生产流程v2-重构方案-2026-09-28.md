# 漫剧生产流程 v2 · 重构方案

> 对标目标:**抖音「动漫短剧」**(竖屏 9:16,以小说/故事为源,动态漫叙事)
> 编制:迫事部(7合1) | 2026-09-23 初版 | **版本:v2.4(2026-09-28 融合导演方法论九件套——新增 S0.5 美术资产盘点、S1 素材合格线、S2 拆解方法论、S4 接力与状态锁)**
> 背景:现行五阶段流程经 Agnes 全流程多次试跑,**从未完整跑通**;已产出结果存在六类系统性问题:
> ① 角色长相/服装每镜漂移 ③ 动作僵硬、口型对不上 ④ 分镜跳跃、剧情稀碎 ⑤ 画风不统一 ⑥ 音画不同步、配乐乱 ⑦ 整体像半成品

---

## 一、根因诊断:为什么现在的流程出不了合格片

### 1.1 三个结构性问题

| # | 问题 | 具体表现 | 本质 |
|---|------|---------|------|
| A | **拼装式生成,没有锚定** | 每个镜头独立生成,一致性靠"生成后检查" | 一致性必须在**生成参数层**锁死(参考图/种子/风格词),检查只是兜底 |
| B | **没有质量闸门,坏料一路流到底** | 单镜崩坏、角色跑偏的镜头会进入下一阶段,最后靠剪辑"挽救" | 每个阶段必须"**不过关不放行**",且带**自动返修环** |
| C | **叙事与音画脱节** | 分镜只做"文本切割"(没有剧作节奏);配乐/配音是最后"贴上去"的 | 短剧的命是**节奏**——情绪曲线必须在剧本期就画好,音画从设计期同步生成 |

### 1.2 为什么 Agnes 跑不通(定位问题)

Agnes 是**通用多模态模型**:文本能力够用(剧本环节 ✅),但——
- 图像端**没有角色参考/面部锚定机制** → 角色必然漂移(问题①⑤);
- 视频端时长、配额、口型能力有限 → 动作/口型/音画必崩(问题③⑥);
- 用它"一把梭"跑全流程,等于**拿通用万金油干专业活**。

> **战略结论(关键)**:
> **千机工坊的价值 ≠ 自己造模型,而是"编排层 + 质检层"** ——
> 把各家最强的模型当"车间"(出图用一家、出视频用一家、配音配乐各用一家),
> **千机工坊负责:流程编排、一致性锚定、质量闸门、返修闭环**。这才是护城河。

## 二、v2 流程总览(七阶段 · 三闸门)

```
S0 立项·剧作化        [短剧改编+情绪曲线]        ← 闸门A:剧本预检+人工定稿
   ↓
S0.5 美术资产盘点     [三步判定→资产表→复核]     ← 资产白名单(唯一美术参考标准)
   ↓
S1 视觉圣经          [角色包+场景包+风格锁]      ← 闸门B:人工定稿(全剧一致性地基)
   ↓
S2 分镜设计          [beat→shot + 连续性设计]
   ↓
S3 关键帧生成        [锚定生成 + 跨镜校验]       ← 闸门C:一致性≥0.85
   ↓  ↺ 自动返修环(重生成 ≤N 轮)
S4 视频片段生成      [首尾帧驱动 + 规避式口型策略]
   ↓  ↺ 单镜返修
S5 音画一体          [旁白/对白/BGM/音效 按情绪曲线]
   ↓
S6 合成·双重质检     [剪辑+字幕+钩子]            ← 成片QC(自动+人工审校)
   ↓  ↺ 定位坏段→回炉
S7 导出·发布·回环    [抖音版+封面+文案+数据反哺]
```

**核心原则**:
1. **质量前置**——把"合格"拆成每阶段的验收指标,不合格不进下游;
2. **一致靠锚定**——同参考图、同种子、同风格词贯穿全镜;校验只做兜底;
3. **嵌套闭环**——单镜返修 < 段落返修 < 整集返修,坏镜头绝不流到剪辑;
4. **音画同源**——情绪曲线同时驱动分镜设计、配乐、配音、剪辑卡点;
5. **人工只在三处**——剧本定稿 / 视觉圣经定稿 / 成片审校;其余自动化;
6. **成本前置**(v2.1 增补)——先小样后全量、同参去重、候选分级、预算熔断,单集花费可视可控;**先便宜挑,再贵出**;
7. **合规分层**(v2.3 修订)——**工具平台责任边界**:版权靠"告知+用户承诺留痕";AI 标识分"平台隐式元数据(我们做)+ 用户显式标识(提示用户)";创作档案全程留存(权利证明+可复现)。

## 三、各阶段详设(输入·输出·闸门·失败处理)

### S-1 合规告知闸门(v2.3 修订 · 工具平台责任边界)

> **定位修正(梁总拍板)**:千机工坊系**工具平台**——不审查内容版权、不掌握用户发布去向。
> 平台职责 = **告知 + 留痕 + 技术辅助**;内容与发布责任 = **用户承担**。

| 项 | 内容 |
|---|---|
| 平台侧 | ① 首次上传/创建项目时弹出**《内容版权与合规告知书》**,用户**勾选确认**(留存账号/时间/版本号);② 提供"发布合规提示"(提醒用户在发布平台主动标识 AI 内容);③ 导出文件自动写入**隐式元数据标识**(工具方技术义务);④ 收到合法侵权通知 → 依规处理(通知-删除) |
| 用户侧 | ① 承诺上传内容拥有权利/合法授权;② 自行承担版权责任;③ 发布时遵守各平台规则(含显式 AI 标识) |
| 交付物 | 《合规告知文件-用户承诺书(草案)》——**已起草**(见桌面千机工坊 / 待产品内置) |

### S0 立项 · 剧作化(Showrunner)

**目标**:把小说变成"**能爆的短剧剧本**"(而不是原文切割)。

| 项 | 内容 |
|---|---|
| 输入 | 小说章节 / 题材选择 / 目标集数与单集时长(默认 60s) |
| 动作 | ① LLM 短剧化改编:3 秒钩子开头 → 每 15 秒一个节奏点 → 集尾悬念钩子;② 产出**节拍表(Beat Sheet)**:每集 8~12 个 beat,每 beat 标注剧情点、情绪标签(接 S1 情绪体系 16 类)、时长预算 |
| 输出 | 分集大纲 + 节拍表(JSON)+ 对白/旁白文本 |
| 闸门 A | 自动预检(钩子强度评分/悬念点数/字数↔时长映射)+ **人工定稿**(剧本必须人看,10 分钟) |
| 失败处理 | 带具体问题反馈 LLM 重写(钩子弱→重写开头;节奏平→插入冲突点) |

### S0.5 美术资产盘点(Art Asset Inventory)(v2.4 新增 · 导演方法论融合)

**目标**:丢小说进生成前,先把"画面里要有什么"定性定量——产出【资产白名单】,根治"道具变形、场景乱加、跨镜重置"。

| 项 | 内容 |
|---|---|
| 输入 | 剧作化后的分集文本(或小说段落) |
| 动作 | ① **三步判定**(实体?→跨 ≥2 镜?→剧情交互?):分 A 核心(参考图+档案)/ B 次要固定(文字锁定)/ C 瞬时动态(仅提示词)/ 一次性背景(仅单镜);② 生成《美术资产拆分表》(A/B/C + 一次性背景 + 高风险清单);③ **人工复核**(剔脑补、控数量、C≤3 项、补兜底句);④ 建立**全局档案**(角色档案/道具档案——状态只能叠加损伤,不能重置) |
| 输出 | 美术资产拆分表(资产白名单)+ 全局档案初版 |
| 铁律 | 后续一切分镜/提示词/生成,不得出现表外 A/B 类物;新核心道具先更新表 |
| 工具 | 《美术资产拆分规范》(主指令+接续指令,可复制)、《资产判定规则》(三步法+案例)、《资产表复核检查清单》 |

### S1 视觉圣经(Visual Bible)

**目标**:建立全剧的"视觉宪法"——这是解决①⑤的地基。

| 项 | 内容 |
|---|---|
| 输入 | 节拍表 + 风格预设选择 |
| 动作 | ① **角色包**:每角色 1 张主视觉 + **多角度参考图组**(正/侧/3-4 视角/表情集),生成后人工筛选、锁定;② **场景包**:主场景参考图(2~6 个),同一场景全部镜头复用同一参考;③ **风格锁**:全剧唯一画风(风格提示词模板固化 + 参考图画风卡) |
| 输出 | 角色库 / 场景库 / 风格卡(均带 ID,全程引用) |
| 素材合格线(v2.4) | 每张参考图上传前过《参考图质检清单》(比例一致 / 无水印文字 / 非 4K / 静态结构无动态元素);多宫格只作库存,成片逐镜参考锚定 |
| 闸门 B | **人工定稿**(不可跳过;角色长相、画风一旦定死,后面全剧沿用) |
| 失败处理 | 角色不满意→重新生成筛选;风格不满意→换预设 |

### S2 分镜设计(Storyboard)

**目标**:beat → shot 的视听化拆解,解决④。

| 项 | 内容 |
|---|---|
| 输入 | 节拍表 + 视觉圣经 |
| 动作 | ① 每 beat 拆 4~8 镜;每镜字段:构图(远/中/近/特写)、运镜、出场角色(引角色ID)、场景(引场景ID)、时长(3~5s)、对白/旁白、情绪标签;② **连续性设计**:视线匹配、180°轴线简单规则、转场预设(同场景硬切/异场景渐黑/时间跳翻页) |
| 输出 | 分镜表(JSON:shot 列表)+ 每镜提示词(CRAFT 五要素:环境/参考/动作/运镜/时间) |
| 检验 | 自动:镜头总数与配乐节拍对齐、角色出场一致性检查;**人工抽查**(3 分钟) |
| 失败处理 | 单 beat 重拆 |
| 方法论(v2.4) | 拆镜遵循《分镜拆解手册》:按"信息变化"拆(非文字段落);5 类叙事单元 / 4 镜结构;衔接四钩子(动作/视线/声音/道具);节奏字标注;终检三问 |

### S2.5 动态分镜预演(Motion Preview)(v2.2 新增 · 省钱又保质)

> 行业核心实践:**>70% 精力花在分镜和动态分镜上**;在进入昂贵生成前,先用最便宜档预演节奏。

| 项 | 内容 |
|---|---|
| 动作 | 用**便宜档**(Seedream flash 图 + Seedance mini/fast)把分镜做成 1~2s 动分(或静帧推拉),拼成无声预演片 |
| 用途 | 人工确认:节奏/张力/构图/转场是否成立;**问题在预演阶段消灭,不带到昂贵生成** |
| 产出 | 预演片(低价)→ 确认后进入 S3 全量 |

### S3 关键帧生成(Keyframes)——生成链起点

**目标**:每镜产出 1~2 张"合格的关键帧";解决①⑤的第一战场。

| 项 | 内容 |
|---|---|
| 输入 | 分镜表 + 角色/场景参考图 + 风格卡 |
| 动作 | ① **锚定生成**:参考图(角色)+ 参考图(场景)+ **固定种子** + 风格词;CRAFT 提示词;② **跨镜校验环**:生成后自动比对——面部特征向量相似度 / CLIP 比对 / 画风一致性打分;**不合格自动重生成(≤3 轮,换角度参考图/微调提示词/局部重绘)** |
| 输出 | 每镜关键帧(首帧,必要时尾帧) |
| 闸门 C | **单镜合格率**:首轮 ≥80%,返修 2 轮后 ≥95%(面部相似度 ≥0.85) |
| 失败处理 | 返修环自动跑;3 轮仍不过 → 标记"人工介入"(换参考图或改分镜) |

### S4 视频片段生成(Video)

**目标**:关键帧 → 动态镜头(3~5s/镜)。

| 项 | 内容 |
|---|---|
| 输入 | 关键帧 + 运动/运镜描述 |
| 动作 | ① 首尾帧驱动 + 运动提示词(走位/镜头运动/表情变化);② **口型策略(重要的导演设计)**:短剧采用"**旁白叙事为主 + 正脸对白少**"——对白镜头多用侧脸/背影/反应镜,规避口型硬伤;必须正脸时→对口型工具兜底;③ 单镜生成后**畸变/崩坏自动检测**;④ **接力与状态(v2.4)**:连续时空段统一"尾帧接力"(下镜参考=上镜尾帧);每镜提示词头部带【全局档案】(角色/道具),损伤只累加不重置;负面词固定套(变脸/伤口愈合/闪烁跳帧…);战斗镜动作控制中幅度(禁腾空大挥砍),时长 3~5s;⑤ 参考图上传前过《参考图质检清单》 |
| 输出 | 镜头视频片段 |
| 检验 | 无崩坏帧、运动合理;人工抽看 |
| 失败处理 | 单镜回炉(种子+提示微调);连续 2 镜不过 → 回 S2 改分镜 |

### S5 音画一体(Audio Design)

**目标**:声音不是"贴"上去的,而是**按情绪曲线设计生成**;解决⑥。

| 项 | 内容 |
|---|---|
| 输入 | 分镜表(含情绪标签)+ 节拍表(情绪曲线)+ 文本 |
| 动作 | ① **旁白**:TTS(音色定人设);② **对白**:角色声线分配;③ **BGM**:按情绪标签从配乐体系生成/匹配(S1 情绪资产直接复用);④ **音效**:踩点(动作/转场);⑤ **节奏对拍**:剪辑点对准音乐重音 |
| 输出 | 完整音轨(旁白/对白/BGM/音效分层)+ 时间轴 |
| 检验 | 音画同步(时长匹配 ±0.2s);情绪一致性(标签比对);响度标准化(-14 LUFS) |
| 失败处理 | 配乐段重生成 / 对白重录(TTS 换参数) |

### S6 合成 · 双重质检(Compose & QC)

| 项 | 内容 |
|---|---|
| 输入 | 镜头片段 + 音轨 + 字幕 |
| 动作 | ① 剪辑拼接(转场/节奏/卡点);② 字幕(烧死,竖屏样式);③ 片头 3 秒钩子 + 片尾悬念;④ **双重质检:自动(黑帧/花屏/时长/分辨率/响度)+ 人工成片审校** |
| 输出 | 成片(1080×1920) |
| 闸门 | 见下方"合格标准表" |
| 失败处理 | 定位坏段 → 回 S4/S3 单段返修(不打回全片) |

### S7 导出 · 发布 · 回环(Delivery & Loop)

| 项 | 内容 |
|---|---|
| 动作 | ① 抖音版导出(1080×1920、封面图、标题文案 AB 3 版);② **合规辅助(v2.3)**:导出文件**自动写入隐式元数据标识**(工具方义务)+ 附"发布提示卡"(提醒用户在各发布平台主动做显式标识——**发布行为由用户执行,平台不掌握发布去向**);③ 工程归档(含**创作档案**:提示词/参数/生成批次/筛选记录——既是权利证明也是可复现资产);④ **数据回环**:发布后盯完播率/3s 跳出/点赞/评论 → 反哺 S0 选题与节奏校准 |
| 输出 | 发布包 + 数据看板入口 |

## 四、"合格"的量化标准(验收表)

| 维度 | 合格线 | 检测方式 |
|---|---|---|
| 角色一致性 | 跨镜面部相似度 **≥0.85**;人工抽检无"换脸/换衣服" | 自动(特征向量)+ 人工抽检 |
| 画面质量 | 无崩坏帧;1080×1920;单镜清晰 | 自动检测 + 抽看 |
| 动作/连贯 | 无明显卡帧;首尾帧衔接自然 | 自动 + 抽看 |
| 叙事 | 3 秒钩子成立;每 15 秒有节奏点;集尾有悬念;**外行看完能复述剧情** | 人工审片 |
| 音画 | 同步 ±0.2s;BGM 情绪与情节匹配;响度 -14 LUFS | 自动比对 |
| 整体 | "像正经动漫短剧号发的作品"(不是 Demo 感) | 人工终审 |

> 任何一项不过 → 定位到对应的 S 阶段返修,**不允许"带着缺陷发布"**。

## 五、技术选型建议(2026 版)

| 环节 | 首选 | 备选/说明 |
|---|---|---|
| 剧本/分镜(文本) | Agnes(已有账户,文本环节够用 ✅) | 或 DeepSeek 等 |
| 关键帧图像 | **火山 Seedream 5.0 Pro**(成片档)/ **5.0 flash**(预览档)——实测在库 | 5.0/5.0-lite 备选;SD/Flux 本地兜底 |
| 视频生成 | **火山 Seedance 2.5 / 2.0**(成片档)/ **2.0-fast / 2.0-mini**(预览档)——实测在库 | 可灵 3.0 作为第二供应商 |
| 口型 | **导演式规避**(旁白+侧脸策略)为主 | 对口型工具兜底(必要镜头) |
| 配音 | TTS 多音色(旁白+角色声线) | — |
| 配乐/音效 | 情绪体系驱动(复用 S1 资产)+ 配乐生成 | — |
| 编排/质检 | **千机工坊本体**(DAG 引擎 + 三道闸门 + 返修环) | 这才是产品核心 |

**成本模型**:按"每集预算 = 图像 N 张 × 单价 + 视频 M 段 × 单价 + TTS/配乐 + 返修冗余(×1.3)"核算;返修率下降 = 直接利润。

## 六、成本控制体系(v2.1 增补 · 防"费用爆炸")

> 背景:此前火山引擎试跑出现"批量生成、费用失控"(一次性生成好几个,花费异常离谱),团队被迫退回 Agnes。本体系把**成本与质量并列为一等公民**。
> 教训:AI 生成按次计费,**每一次提交都是真金白银**;失控多来自——多候选滥发 / 整批提交 / 超时重试双重计费 / 无上限重试 / 未挑先跑高清。

### 6.1 费控五件套

| # | 机制 | 说明 |
|---|------|------|
| ① | **预检前置** | 生成前干跑校验(输入完整/提示词合规/引用ID有效),挡住废生成 |
| ② | **先小样后全量** | 先 1~2 镜预览档试跑、人工确认,再放大批量——**绝不整集一次性全提交** |
| ③ | **去重锁** | prompt+参数 hash 去重,同参数不重复提交;网络超时**先查任务状态再决定是否重试**(防"超时重试=双重计费") |
| ④ | **预算熔断** | 单镜/单集/单日三级预算上限,达到阈值**自动暂停**,人工确认才放行 |
| ⑤ | **成本遥测** | 每次生成记账(模型/次数/费用),单集实时花费看板,超预算告警 |

### 6.2 候选策略分级(多生成要花在刀刃上)

- **普通镜头**:1 个候选;
- **关键镜头**(开场钩子 / 剧情转折 / 集尾悬念):2~3 个候选,且**先出预览档(低清/便宜)挑选 → 定稿只跑 1 次成片档(高清/贵)**;
- 🚫 禁止"所有镜头全量多候选"——这正是费用失控的头号来源。

### 6.3 单集账本示例(60s · 约 30 镜)

| 项 | 档位 | 数量 | 备注 |
|---|---|---|---|
| 关键帧(预览档) | 低 | ~30×(1.3 返修冗余) | 先便宜挑 |
| 关键帧(成片档) | 中 | 30(定稿后一次) | 只跑定稿 |
| 视频(预览档试跑) | 低 | 3~5(仅关键镜头) | 人工确认 |
| 视频(成片档) | 高 | 30(每镜一次) | 严格去重 |
| TTS / 配乐 | 低 | 1 集 | — |
| **纪律** | — | — | 单集上限先设阈值(按 P0 实测校准),超标即暂停 |

### 6.4 口径与上限线(v2.2)

- **口径警告**:对外报"成本"必须标明口径——"纯算力成本"(我们:~80-120 元/集)≠ "综合成本"(行业均值 800-1000 元/分钟,含人力);别让对标失真。
- **单集上限线(初始值,P0 校准)**:纯算力 **≤150 元/集** 触发预警;超出即熔断复核。

### 6.5 账号侧最后一道保险

- **火山引擎控制台 → 费用中心**:设置**预算预警 + 费用限额**(每日/每月),从账号层面兜底;
- 保留 Agnes/本地模型作为**文本档与应急档**:剧本分镜走文本模型,画面链主用火山;供应商可切换。

## 七、实施路线(三步走)

### P0(1~2 周):真链路最小闭环(**带费控**)
- 选 1 集 300~500 字小说 → 手工走通 S0→S7 全链(重点:**用真模型,不用 mock**);
- **同步启用费控五件套**(预检/小样/去重锁/熔断/遥测),P0 期间即设**单集预算阈值**——绝不让"费用失控"重演;
- 产出:第一版"真"成片(允许粗糙)+ **真实单集成本数据** → 定位瓶颈与成本基线;
- 交付:链路跑通证据 + 瓶颈清单 + 成本账单。

### P1(2~4 周):质量闭环
- 加三道闸门(一致性校验 / 返修环 / 成片 QC)+ 音画一体;
- 目标:同一集的"合格率"从首版拉到 **≥90%**(按验收表);
- 交付:合格率对比报告 + 闸门配置手册。

### P2(1~2 月):批量化 · 产品化
- 多集生产(3~5 集连续)、题材模板化(仙侠/都市/悬疑…);
- 把整条 v2 流程做进千机工坊编辑器(自动产线:一键从小说到成片);
- 数据回环上线(发布数据→选题迭代)。
