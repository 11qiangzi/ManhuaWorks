## 一、研究概述

### 1.1 背景与目标
漫改功能是将小说/剧本一键转化为分镜动画视频的核心创作模块，全流程共 **10 步**：项目设置 → 上传小说 → 角色设定 → 场景设定 → 分镜编排 → 镜头视频 → 合成视频 → 画质提升 → AI 配音 → 合成导出。用户要求"从用户角度测试全流程的页面 UI 体验与功能性缺点，出具改进报告"。

### 1.2 方法说明（重要边界）
- 本次为**专家启发式评估 + 认知走查**，基于代码实证（逐行核对 `StoryboardEditorView.vue` 11607 行、落地页、stores、api/byok）与架构知识。
- **未做真人可用性测试**（无可用被试、未接分析埋点）。因此所有问题均标注**代码证据（文件:行号）**，结论可复核、可溯源。
- 真实用户验证（5–8 人 moderated test + 行为埋点）列为后续计划（见第六节），以补足"用户主观感受"维度。

### 1.3 评估结论速览
| 维度 | 现状评级 | 关键结论 |
|---|---|---|
| 流程框架/引导 | 良好 | 10 步 stepper + 微文案 + 落地页模板引导到位 |
| 状态可见性 | 中等 | 有进度总览与 generating 态，但缺总体进度%与完成播报 |
| 流程完整性闸门 | 差 | 步骤导航**无完成度校验**，可"假完成"空跑 |
| 数据持久化 | 中等 | 草稿自动保存完善，但依赖 sessionStorage，关页有丢稿风险 |
| 功能性缺陷 | 中等 | localhost-only 图片 URL 致重生成失参考图 |
| 可访问性(a11y) | 偏弱 | 有 alt/focus，缺 aria 角色/键盘导航/状态播报 |
| 响应式 | 偏弱 | 仅 1 个 768px 断点，10 步在移动端体验存疑 |
| 主题一致性 | 中等 | CSS 变量化但深色兜底值多，浅色主题待核实 |
| 内容一致性 | 差 | "千机工坊/漫改工坊/动画序列"命名割裂 |

## 二、关键发现（按严重度分级，均附代码证据）

### 🔴 高优先级（直接影响完成率与成品质量）

#### F-01 步骤导航无完成度校验，可"假完成"空跑
- **证据**：`StoryboardEditorView.vue`
  - L92-93：`goNext()`/`goPrev()` 仅切换 `currentStepIndex`，无任何校验。
  - L6444：底部"下一步"按钮 `@click="() => { markCompleted(currentStepIndex); goNext() }"` —— **无论本步是否真正完成，一律标记完成并前进**。
  - L3210：`function canProceed(): boolean` 已定义，**全局仅此一处定义、从未被任何按钮/守卫调用（死代码）**。
- **用户影响**：用户可一路点过 10 步而不填小说、不生成角色；下游步骤用空数据生成，轻则产出空白视频、重则调用链报错。步骤指示器的"已完成"绿勾**不真实**，误导用户对进度判断。
- **建议**：将 `canProceed()` 接入"下一步"禁用逻辑；按步骤定义最小完成条件（如：上传小说非空、至少 1 角色、分镜数>0、至少 1 镜头视频已生成）；未满足时按钮置灰并 hover 提示缺什么。

#### F-02 单文件 11607 行"巨组件"，可维护性与首屏性能风险
- **证据**：`StoryboardEditorView.vue` 共 11607 行（script 1–4947 / template 4949–6478 / style 6478–11607）；10 步全部内联。
- **用户影响**：虽不直接等同于 UI 缺陷，但带来（a）首屏 JS 体积大、初始化慢；（b）任意一步改动回归成本高、易引入不一致；（c）深度 watch/大对象响应式（同文件多处 `watch` 大数组）可能造成交互卡顿。
- **建议**：按步骤拆为 `steps/StepSetup.vue`、`StepUpload.vue`… 子组件 + 各自 store 切片；长列表（分镜/镜头）用虚拟滚动；大对象 watch 改为 `shallowRef` + 显式触发。

### 🟠 中优先级（显著影响体验，但不阻断主流程）

#### F-03 草稿持久化依赖 sessionStorage，关页即丢稿风险
- **证据**：
  - L4679：草稿自动保存到 `sessionStorage`（防抖 1000ms，L4666）。
  - L4730-4742：sessionStorage 接近 5MB 时**降级**——丢弃大 URL 只存元数据，"URL 数据未保存"。
  - L4866：`beforeunload` 仅"提醒"，不阻止关闭。
  - L4778：恢复时"优先使用项目库（DB）数据，仅 DB 未加载时从 sessionStorage 恢复"。
- **用户影响**：sessionStorage 在**标签页关闭/崩溃后即清空**。未登录或尚未建项目时，用户辛苦填的设定可能因一个误关页而丢失；5MB 降级还会静默丢图。
- **建议**：草稿实时同步至服务端 project-service（已有 DB 与 projectStore）；关闭前若有未同步草稿，弹**可撤销的保存确认**而非单纯提示；大图改存对象存储并返回可访问 URL（顺带解 F-04）。

#### F-04 生成图 URL 为 localhost-only，单视图"重新生成"失参考图（功能性落差）
- **证据**：L3651 / L3688 / L3744 注释明确："persisted image URLs are localhost-only, inaccessible to Seedream's API"。
- **用户影响**：步骤描述承诺"不满意重新生成"（L58），但重生成单视图时无法把已生成图作为参考图传给 Seedream，导致重生成结果**风格/构图漂移**，与用户"微调"预期不符。
- **建议**：生成图落地对象存储，存储**公网可访问 URL**；重生成时携带参考图。属功能性修复，优先级高。

#### F-05 可访问性(a11y)薄弱，键盘/读屏用户受阻
- **证据**：
  - 正面：图片基本带 `:alt`（L5189/L5208/L5392 等）、输入有 `:focus` 样式（L6755 等）。
  - 缺失：**无 `role`/`aria-*` 语义**；步骤条用 emoji 图标无 `aria-label`（L53-62 定义，模板未加）；**无 `aria-live`** 播报 AI 生成开始/完成；stepper 不可键盘聚焦跳转；无跳转链接与标题层级。
- **用户影响**：屏幕阅读器无法获知"当前第几步/生成是否完成"；键盘用户难以在 10 步间导航；不符合 WCAG 2.1 AA。
- **建议**：步骤条加 `role="tablist"/tab` + `aria-selected` + 键盘方向键；生成状态容器加 `aria-live="polite"`；所有图标按钮补 `aria-label`；建立 `h1–h3` 标题层级。

#### F-06 AI 长任务反馈仅靠 per-item spinner，缺总体进度与完成播报
- **证据**：本视图未使用架构所述的 `subscribeProgress` WS（全文件 0 处 `subscribeProgress`）；靠 `view.generating` 等布尔态显示 spinner（L3654/L3748 等）；视频生成（步骤 6/7）耗时分钟级。
- **用户影响**：长时间无总体进度%/ETA，用户易误判"卡死"而重复点击或离开；完成后无明确提示（无 aria-live、无 toast）。
- **建议**：接入 `subscribeProgress` 拉取任务百分比并展示进度条+预计剩余；完成后 toast + aria-live 播报；生成中禁用重复提交（已有 `:disabled` 基础，需统一）。

#### F-07 响应式覆盖有限，移动端/平板体验存疑
- **证据**：全文件仅 **2 个 `@media (max-width:768px)`**（L7013/L7501）；步骤条 `.sbe-stepbar` 隐藏滚动条横向滚动（L6572）。
- **用户影响**：10 步流程在平板(768–1024)、中屏仅 1 个断点兜底；步骤条横向滚动在手机上"当前步"定位不直观，易迷失。
- **建议**：补充 1024px/1280px 断点；步骤条在窄屏改为"当前步 X/10 + 可展开列表"而非裸滚动；分镜/镜头网格列数随屏自适应。

#### F-08 浅色主题兜底不全（对比度隐患）
- **证据**：大量 `var(--bg-primary, #0E0F12)`、`var(--text-muted, #64748B)` 等**深色兜底值**（L6494/L6513/L6548 等）；若全局 theme 未提供浅色变量，组件将落在深色兜底，浅色模式下文字/背景对比度可能不达标。
- **用户影响**：浅色主题下可读性下降，a11y 对比度风险。
- **建议**：确认全局 theme 同时定义 light/dark 变量；移除或修正硬编码深色兜底为中性值；用对比度检查工具（如 axe）过一遍浅色主题。

#### F-09 品牌/命名不一致，用户认知割裂
- **证据**：代码 `branding.ts` 品牌为「千机工坊」；落地页称"动画序列/分镜"；用户与部分文档称"漫改工坊/ManhuaWorks"；编辑器内步骤 label 用"漫改"语义。
- **用户影响**：同一功能多套叫法，新用户不易建立心智；SEO/分享文案混乱。
- **建议**：以 `@/config/branding(BRAND)` 与 `@/config/naming(MODULE_NAMES)` 为唯一真相源，全站统一"漫改工坊"对外名（或确认"千机工坊"为总品牌、漫改为子模块），文案零硬编码。

### 🟡 低优先级 / 待实机核实
- **F-10 错误态可见性**：`status` 枚举含 `'error'`（L2867），但错误是否给出**明确原因 + 一键重试 + 超时处理**需实机验证（建议接入后补错误边界组件）。
- **F-11 深度 watch 性能**：同文件对大数组（分镜/镜头）存在深度 watch，交互密集时可能掉帧，建议 profiling 确认。

## 三、用户旅程痛点地图（10 步）

| 步骤 | 用户目标 | 痛点（对应发现） | 情绪 |
|---|---|---|---|
| 1 项目设置 | 定集数/画风/比例 | 选项多但无"推荐默认+理由" | 中性 |
| 2 上传小说 | 导入文本 | 仅 sessionStorage 持久化，关页丢稿（F-03） | 焦虑 |
| 3 角色设定 | AI 提取角色+主视觉 | 重生成失参考图致漂移（F-04）；步骤可跳过（F-01） | 疑惑 |
| 4 场景设定 | 生成场景图 | 同上 | 疑惑 |
| 5 分镜编排 | 拆分+预览+改提示词 | 巨组件致卡顿风险（F-02）；无完成校验（F-01） | 中性偏疲 |
| 6 镜头视频 | 逐镜头生成（分钟级） | 无总体进度/ETA、无完成播报（F-06）；失参考图（F-04） | 焦虑/易弃 |
| 7 合成视频 | 拼接整集 | 同上；长任务无反馈 | 等待 |
| 8 画质提升 | 超分增强 | 状态可见性一般 | 中性 |
| 9 AI 配音 | 分段配音 | 无 aria-live 播报（F-05） | 中性 |
| 10 合成导出 | 导出成品 | 若前序"假完成"则导出空白（F-01） | 挫败（若踩坑） |

> 旅程最大风险点：**步骤 2（丢稿）** 与 **步骤 6（长任务无反馈+可假完成）**。

## 五、改进建议（优先级 + 可落地）

### 高优先级（立即）
1. **接好 `canProceed()` 闸门**（F-01）：下一步按钮按步骤最小完成条件禁用；死代码激活。预期：虚假完成率→0，空白产出显著下降。
2. **修复 localhost-only 图 URL**（F-04）：图落对象存储返回公网 URL，重生成带参考图。预期：重生成风格一致性提升。
3. **草稿实时同步服务端**（F-03）：替代 sessionStorage 单点；关闭前可撤销保存确认。预期：丢稿客诉→0。

### 中优先级（本迭代）
4. **a11y 加固**（F-05）：stepper 键盘可达 + aria-live 状态播报 + 图标按钮 aria-label。
5. **长任务进度体系**（F-06）：接入 `subscribeProgress` 百分比/ETA + 完成 toast。
6. **响应式补断点**（F-07）：1024/1280 断点 + 窄屏步骤条改"X/10+展开"。
7. **浅色主题核对**（F-08）：确认 light 变量完整 + 修深色兜底 + axe 过检。
8. **命名统一**（F-09）：全站走 BRAND/MODULE_NAMES，消除多套叫法。

### 低优先级（后续）
9. **组件拆分**（F-02）：10 步拆子组件 + 虚拟滚动 + shallowRef，降体积提性能。
10. **错误边界组件**（F-10）：统一错误原因 + 重试入口 + 超时处理。

## 六、成功度量指标
- **流程完成率**：从进入漫改到成功导出比例，目标 +30%。
- **步骤"假完成"率**：完成态但关键产物为空的比例，目标 0。
- **丢稿相关客诉/反馈**：目标归零。
- **重生成一次通过率**（无需二次返工）：目标 +25%（参考图修复后）。
- **长任务 abandonment**：步骤 6/7 中途离开率，目标 -40%（进度体系上线后）。
- **a11y**：axe 自动检测 0 严重问题；浅色/深色对比度达标 WCAG AA。
- **响应式**：768/1024/1440 三档无横向溢出、步骤条可达。
