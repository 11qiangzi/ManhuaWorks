### 1.2 交付铁律

```
╔═══════════════════════════════════════════════════╗
║  所有交付物 = 录屏(.mp4) 或 截图(.png) + Bug 描述  ║
║  口头汇报 = 不合格 = 打回重测                      ║
║  无证据 = 视为未测                                 ║
╚═══════════════════════════════════════════════════╝
```

- 录屏标准：≥30 秒，展示完整操作路径
- 截图标准：全屏截图，含浏览器地址栏/设备型号
- Bug 描述格式：`[站点]-[页面]-[严重程度] 描述`
- 严重程度：🔴 P0(阻断) / 🟠 P1(严重) / 🟡 P2(一般) / ⚪ P3(建议)

### 1.3 测试态度

```
你不是开发者，不是编辑，不是设计师。
你是一个第1次访问这个网站的普通用户。
你对这个产品 0 了解，0 耐心，0 容忍度。

任何让你皱眉的体验 → 就是 Bug。
任何让你想关掉页面的瞬间 → P0。
任何让你困惑 3 秒以上的交互 → P1。
```

## 二、跨部门测试矩阵

### 2.1 林知行 @ 内容部 — 内容盲测

**测试对象**：Web 主站 + Studio 工作台的所有可见文字/图片

**检查项 9 条**：
1. 错别字：逐段阅读 web / studio 每页文字
2. 断句：中文标点规范、段落间距
3. 图片加载顺序：首屏是否先出现文字再等图
4. 图片加载失败：broken image 是否被替换为占位符
5. 弃读风险：阅读到页面 50% 时是否有动力继续
6. Alt 文本：图片缺失时 alt 属性是否有意义
7. 链接有效性：页内链接是否 404
8. 统一用语：同一概念是否使用相同词汇
9. i18n/中文：是否有中英混杂、翻译不全

**输出**：`D:\ManhuaWorks\docs\testing\content\LINZHIXING_BLIND_CONTENT_2026-06-11.md`
**证据**：每页 ≥ 1 张截图，问题页 ≥ 1 段录屏

### 2.2 林染 @ 前端部 — 交互盲测

**测试对象**：5 站全部页面的交互元素

**检查项 12 条**：
1. 每个按钮 → 点下去，看有没有反应
2. 每个弹窗/Modal → 打开→关闭→再打开
3. 每个表单 → 填正常值→填错误值→提交
4. 每个下拉菜单 → 展开→选一项→再展开
5. 每个链接 → 点击→检查目标页
6. 每个 Tab 切换 → 循环点击所有 Tab
7. 每个 Toast/通知 → 触发→等待消失
8. Loading 状态 → 网络慢时是否有 loading 提示
9. Empty 状态 → 无数据时是否有友好提示
10. Error 状态 → 接口报错时是否有友好提示
11. 键盘导航 → Tab/Enter/Esc 是否可用
12. 焦点顺序 → Tab 键焦点是否合理流动

**输出**：`D:\ManhuaWorks\docs\testing\frontend\LINRAN_BLIND_UI_2026-06-11.md`
**证据**：每个检查项 ≥ 1 张截图/录屏

### 2.3 谢擎 @ 后端部 — 后端盲测 + 交叉点前端

**检查项 10 条**：
1. 每个 API 端点 → curl/Postman 手动调用，验证返回状态码
2. 鉴权接口 → 带 Token / 不带 Token / 错误 Token 三种情况
3. 分页接口 → page=0 / page=-1 / page=超大值 边界测试
4. 超时处理 → 模拟慢查询，验证超时机制
5. 数据库连接 → 模拟断连重连
6. Redis 缓存 → 验证缓存命中/失效
7. 日志记录 → 验证错误日志是否完整
8. 限流机制 → 验证 rate limit 是否生效
9. WebSocket → 验证连接/断连/重连
10. 交叉点前端 → 用林染的测试清单，从后端视角补充

**输出**：`D:\ManhuaWorks\docs\testing\backend\XIEQING_BLIND_BACKEND_2026-06-11.md`
**证据**：每个接口 ≥ 1 张截图（curl 输出或 Postman 截图）

## 三、Bug 提报流程

### 3.1 标准模板

```markdown
### Bug #N — [站点] [页面] [严重程度]

- **发现人**: 林知行/林染/谢擎/赵千影
- **发现时间**: 2026-06-11 HH:MM
- **严重程度**: 🔴 P0 / 🟠 P1 / 🟡 P2 / ⚪ P3
- **复现步骤**:
  1. 打开 [URL]
  2. 点击 [按钮]
  3. 观察到 [现象]
- **期望行为**: [应该怎样]
- **实际行为**: [实际怎样]
- **证据**: [截图/录屏路径]
```

### 3.2 提交流程

```
发现人 → 填写模板 → 提交给程构审核
         ↓
程构审核 → 确认严重程度 → 分配修复人
         ↓
修复人 → 修 Bug → 截图证明已修 → 提交程构复核
         ↓
程构复核 → 打勾 ✅ / 打回 ❌
```

## 四、验收标准

### 4.1 合格线

| 检查项 | 标准 |
|--------|------|
| 已测试页面 | 5 站全部 46 页面 100% |
| 已测试 API | 全部 42 端点 100% |
| 已测试设备 | 6 种视口 100% |
| P0 Bug | 0 个（全部修复） |
| P1 Bug | ≤ 3 个 |
| P2 Bug | ≤ 10 个 |
| 录屏/截图 | ≥ 50 张/段 |

### 4.2 不合格即打回

以下情况视为不合格：
- 缺任何一站任何一页的测试截图 → 打回
- 口头说"没问题"但无截图 → 打回
- P0 Bug 未修复就交付 → 打回
- 同一个 P1 Bug 出现 2 次以上 → 打回
- 提交时间超时未报备 → 打回
